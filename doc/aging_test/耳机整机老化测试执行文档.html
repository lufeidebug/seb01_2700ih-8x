1. 文档说明与适用范围

本文档依据客户提供的《老化参考.xlsx》，结合本项目（恒玄 BES2700IH 平台耳机整机）的实际硬件配置裁剪整理，用于产线整机老化测试的执行与记录。

项目说明
适用对象本项目耳机整机（左耳 / 右耳），单只独立老化
测试阶段试产验证 + 量产抽检 / 全检（按产线策略）
测试性质电应力老化（非机械应力、非环境箱老化）
环境条件常规产线环境（常温），不需温箱或老化房
执行方式通过 pogopin 单线 UART 下发老化指令启动，自动循环；过程数据写入 sndp_aging_test_section（0x1000）
单机时长试产约 137 min；量产约 112 min（详见第 4 节）
执行顺序约束

电应力老化不要用电量作为入口条件——避免前道机械应力老化后低电，导致电应力老化无法启动。（此条来自参考表格产线老化备注）

关于 VSENSOR 供电的重点提示

DA217E 与 SSH401A 共用 VSENSOR 供电。这意味着：

  • VSENSOR 一旦异常，两颗传感器会同时失效——测试中若出现两个传感器同时判失败，应优先排查 VSENSOR 而非传感器本身
  • 因此本方案将 VSENSOR 供电检测单独列为一个小项（A5），并要求在传感器测试前先执行
  • 两颗传感器若挂在同一条 I2C 总线上，总线压力测试（B8）需覆盖该总线

4A. 老化测试指令说明（pogopin 单线 UART）

老化指令不走 debug 串口文本 AT，而是走项目通信协议，由治具经 pogopin 单线 UART 发给耳机。配置与状态全部使用定长数值，不用 ASCII，也不按名称匹配大项：0x7D 固定 27 字节 = 9 × [大项ID + 是否测试 + 目标次数]，严格按大项 ID 0..8 顺序。

配置与启动是分开的两条指令

启动指令 0x7A 不再携带参数。流程是：先用 0x7D 下发配置（各项目标轮次），再用 0x7A 启动，此时耳机使用已保存的配置。

  • 0x7D 配置：写入 cfg.big_cfg[] 并持久化到 flash；不影响正在运行的测试
  • 0x7A 启动：若没有任何大项被配置则返回执行失败
  • 0x7E 查询配置：读回当前 8 个大项的"是否测试"与目标次数
物理口与前置条件
  • 接口：pogopin 单线 UART，115200, 8 数据位, 无校验, 1 停止位，半双工
  • 协议路径：PATH = 0x02（SNDP_COMM_PATH_POGOPIN）
  • 发送方：产测治具 FROM = 0x05（SNDP_COMM_DEVICE_ATE）；接收方按被测耳填写 TO = 0x01（左）或 0x02（右）
  • 耳机侧在 app_init() 中、通信模块初始化之后调用 sndp_aging_test_init()。正常开机和软/硬重启都会走到，重启后才能从老化分区续测
  • 单线半双工：治具发完一帧后切到接收，再读回包。不要在发送期间同时监听本端回环

4A.1 帧格式

FLAG(1) + FROM_TO(1) + PATH(1) + CMDID(1) + DLEN(2, 大端) + DATA(n) + CRC16(2, 大端)

FLAG     = 0xFE
FROM_TO  = (FROM << 4) | TO     例: 治具→左耳 = 0x51, 治具→右耳 = 0x52
PATH     = 0x02
DLEN     = DATA 字节数, 高字节在前
CRC16    = 对 FLAG 到 DATA 末字节计算, 初值 0xA1B2, 高字节在前
           （与 sndp_comm_protocol_calc_crc16 一致; 调试时也接受 CRC = 0xFFFF）

4A.2 指令一览

指令 CMD 请求 DATA 应答 DATA
配置 0x7D 27 字节 = 9 × [大项ID(1) + 是否测试(1) + 目标次数(1)]，严格按大项 ID 0..8 顺序（格式见 4A.3）。发 1 字节 0x00 表示清除配置并退出老化 1 字节错误码
启动 0x7A 0 字节。使用已下发的配置启动；未配置任何大项时返回执行失败 1 字节错误码
停止 0x7B 0 字节。停线程并把分区里的"老化中"标志清掉；已完成轮次与配置保留 1 字节错误码
查询状态 0x7C 0 字节 89 字节，见 4A.5

4A.3 配置数据（CMD 0x7D）

数据是定长数值，共 27 字节：固定 9 组，每组 3 字节，严格按大项 ID 从 0 到 8 排列。

每组 3 字节：
  大项ID(1)     0~8，必须与本组下标一致
  是否测试(1)    1 = 要测, 0 = 不测
  目标次数(1)    0~255（本字段只有 1 字节，上限 255）

9 组顺序（= 大项 ID）：
  0 charge(保留)  1 sram   2 flash  3 soft_rst  4 hard_rst
  5 mid           6 high   7 bus    8 终检(传感器复检 + 检测充电 + 补电)
9 项一次全带，不勾的也要带

不管某个大项要不要测，这 27 字节里都必须有它，"是否测试 = 0" 就是没勾。不要只下发勾选项——早期 ASCII 格式只发勾选项，耳机侧会把没下发的项保留成上一次的配置，会出现"没勾硬重启、查询回来又勾上了"的问题。

8 号"终检"是收尾大项，目标次数一般填 1

它跑三个小项：传感器复检 → 检测充电（等耳机进入充电，最长 30 s，超时判充电失败）→ 补电（低于 80% 持续补电，到 80% 停充，落点期望 80%~85%）。

注意：补电是阻塞过程，低电量时可能持续几十分钟（内部每 1 s 复查一次电量与温度，可随时被上位机停止/退出，超过 AGING_BAT_TOPUP_TIMEOUT_S=3600 s 判失败）。所以这一段要用充电仓供电，不要中途拔仓。

两条指令别搞混
  • 0x7D 只写配置，不启动。若老化正在运行，改配置不会影响本轮（运行中的目标轮次已固化到过程数据）。
  • 0x7A 才启动。重复发启动会丢弃上次进度、重新开始：固件会把过程数据清零并重写目标轮次。
  • 配置必须"至少一个大项 是否测试=1 且 目标次数 > 0"，否则 0x7A 返回执行失败；一个大项都没勾时 0x7D 直接按"清除配置并退出老化"处理。

上位机怎么判"这一项测不测"

协议里没有单独的"是否测试"位，只有 target_cycle。所以固件上报时把本次不跑的大项统一压成 0， 上位机按下表显示（勾选框只在"第一帧报文到达之前"作临时显示）：

  • target_cycle == 0 → 跳过
  • run_cycle ≥ target_cycle → 通过
  • 该大项就是 curr_big_id → 测试中（运行中）/ 已停止
  • 已被设备跳过过（进入过更高的大项）→ 失败
  • 其余 → 等待

如果这里报非 0，界面会把没勾选的大项显示成"等待"，甚至会因为该大项从未被进入而误判成"失败"。

老化在耳机自己的本地流（AUD_STREAM_ID_3，16 kHz/16 bit/单声道）上放粉噪，而手机推过来的 A2DP 流是 48 kHz/24 bit/立体声，两者共用同一颗 codec。手机会赢，因为老化流不参与音频焦点仲裁：

11:14:53.971  (d0) ::A2DP_EVENT_STREAM_STARTED ... a2dp_streaming_changed 3   ← 手机开始推流
11:14:54.152  af_thread:WARNING: id=3 stream=0 hdlr intvl ERROR: 191799 us     ← 老化播放流被抢
11:14:54.892  af_thread:WARNING: id=3 stream=0 lost 255 signals
11:15:01.841  af_thread:WARNING: id=3 stream=0 hdlr intvl ERROR: 6836042 us     ← 6.8 s 没跑 = 静音
11:15:12.586  [sample_rate]old=48000 new=16000 / [bits]old=24 new=16        ← 老化流把 codec 抢回来

表现为治具听到「突然无声」，af_thread 刷 hdlr intvl ERROR／lost signals。 固件已在 E1 之前加了前置检查：会先发 AVRCP PAUSE 停掉手机播放；停不下来就报 13， 不会让它变成看不出原因的「音频失败 8」。产线治具上请保持手机只跑 SPP 桥接、不播放音乐。

失败位置怎么看

失败大项/小项不单独上报。上位机可结合 curr_fail_code 与 run_cycle[] 判断：某个大项的 run_cycle 明显小于 target_cycle 且之后的大项已在推进，通常说明该大项曾失败并跳过大项剩余轮次。

4A.6 查询配置应答（CMD 0x7E，28 字节）

偏移长度说明
01error，0 成功
1279 组 [ 大项ID(1) + 是否测试(1) + 目标次数(1) ]，与 0x7D 的下发数据布局完全相同，严格按大项 ID 0..8 顺序
 
偏移 1 + i×3 + 0 = 大项ID    0~8，必须等于 i
偏移 1 + i×3 + 1 = 是否测试   1 = 要测, 0 = 不测

00 | 00 01 00 01 01 01 02 01 01 03 01 0A 04 00 00 05 01 12
     06 01 12 07 01 0A 08 01 01
↑error  ↑ 这 27 字节应与下发的 DATA 逐字节一致

回读结果可直接与下发数据逐字节比对：布局相同，一致即说明配置已正确写入。

4A.7 错误码

值含义常见原因
0x00成功—
0x07CRC 错误帧尾 CRC 与计算值不一致，且不是 0xFFFF
0x19执行失败发 0x7A 启动但没有任何大项被配置
0x20参数长度非法0x7D 的 DATA 长度既不是 27 字节也不是 1 字节
0x21参数超范围 / 无法解析0x7D 里某组的大项 ID 与组下标不一致，或"是否测试"不是 0/1
0x22不在测试模式被产测模式校验拦截，见下方说明
0x23 / 0x24电池盒电量错误 / 蓝牙未初始化完成其它产测指令的通用错误码
0x22 不在测试模式

工程启用了产测模式校验：未进入测试模式时，老化指令会被拒绝。0x7A/0x7B/0x7C/0x7D/0x7E 已加入白名单（走 SPP 也会放行），但配套的其他产测指令仍需先切到测试模式。

若 0x7C 能通而 0x7D 返回 0x22，说明耳机固件早于 0x7D/0x7E 版本（白名单里还没有它们），需重新编译烧录。

4A.8 过程数据与重启续测

过程数据不占用产测 flag，单独写在 Flash 分区 sndp_aging_test_section，大小 0x1000。存储结构为：

老化相关的两个 Flash 分区
  • sndp_aging_rw（0x1000，4KB）：擦写专用，只给 FLASH 大项做「擦除 → 写随机数 → 回读 CRC」用，不存任何需要保留的数据；每次老化会被擦写 5 × 轮次 次。
  • sndp_aging_test（0x1000）：过程数据，重启续测靠它恢复。

两者在链接脚本里是相邻的独立分区，擦写分区在过程数据分区之前，互不影响。

sndp_aging_store_data_t {
    magic      = 0xA5A5A501        // 校验头
    checksum                       // 除本字段外全结构累加后 ^ 0xA5A55A5A
    cfg                            // 9 个大项的 enable + target_cycle
    test_data {                    // 全部测试数据
        in_aging, finished
        total_run                  // 累计轮次
        current_big_id, current_sub_id
        elapsed_ms                 // 已运行时长基数(ms)
        big_result[9] { big_id, result, target_cycle, done_cycle,
                        fail_item, fail_code, start_ms, elapsed_ms }
    }
}
时机分区里写什么
配置指令 0x7D写入 cfg。不改变运行中的测试（其目标轮次已固化在 test_data）
启动指令 0x7A重建 test_data：in_aging = 1、finished = 0、轮次清零、按配置写入各项目标轮次；随后从第一个有效大项开始
进入某个大项记录该大项起点，并整块落盘
某大项一轮通过累加该大项 done_cycle 与总 total_run，落盘
某小项失败记该大项 result = 失败 及 fail_item/fail_code，落盘，然后跳过该大项剩余轮次进入下一大项
重启前先累加轮次并落盘，回读校验通过才真正重启；同时固化已运行时长
全部大项走完finished = 1，current_big_id = 0xFF
温度超红线记当前大项失败（code = 5）并终止老化
停止指令 0x7Bin_aging = 0，已完成轮次与配置保留；下次开机不会续测
退出 0x7D + 0x00清空 cfg 与 test_data
软重启 / 正常开机sndp_aging_test_init() 读回。若 in_aging = 1 且未测完，从记录的 current_big_id 继续；已测完或已停止只打印日志，不自动重跑
重启续测的两个关键点
  • 重启前落盘：轮次与已运行时长先写入 flash 并回读校验，通过后才调用 sndp_app_reboot，避免重启丢进度。
  • 重启后等待：恢复到含重启小项的大项时，先等 AGING_REBOOT_RESUME_WAIT_MS（30 s）再执行下一步。

4A.9 注意事项（上位机与治具）

协议已变更，务必同步上位机
  • 0x7C 查询应答由 37 字节改为 89 字节，字段顺序也变了（新增 total_times、elapsed_ms、curr_big_id/curr_sub_id、run_time_s[9]，删除 stage/fail_stage/fail_item/item_skip_mask/cfg_cycle）。旧解析不兼容。
  • 启动指令 0x7A 由"携带参数"改为"无参数"，配置改由 0x7D 下发。
  • 0x7D/0x7E 由 ASCII 改为定长数值：27 字节 = 9 × [大项ID(1) + 是否测试(1) + 目标次数(1)]，不再按名称匹配；单个大项的目标次数上限由 65535 变为 255。旧脚本 / 旧上位机不兼容。
  • 8 号"终检"大项：传感器复检 → 检测充电（curr_sub_id = 13，持续查充电状态，最长 30 s，超时判充电失败）→ 补电（curr_sub_id = 4，低于 80% 持续补电，到 80% 把充电电流置 0 停充）。跑到这两个小项时上位机分别显示"等待进入充电""补电中"。
项目说明
配置与启动分离必须先 0x7D 配置，再 0x7A 启动；只发启动会返回执行失败
配置数据格式定长数值：27 字节 = 9 × [大项ID(1) + 是否测试(1) + 目标次数(1)]，不勾的项也要带（是否测试 = 0）；单个大项目标次数上限 255
终检与补电耳机侧 8 号"终检"大项自带：传感器复检 → 等进入充电（最长 30 s）→ 补电到 80% 后停充（充电电流置 0）。上位机的"充电检测"按钮是不跑老化时的单独复核（30 s，要求"在充电 且 电量 ≥ 80%"）
重复启动0x7A 会丢弃上次进度重新开始（过程数据清零）。不要对未完成的样机重复发启动
硬重启跳过hard_rst 被 AGING_SKIP_HARD_RST 强制置 0，配置里带不带都不执行
charge 槽位协议保留的槽位 0，当前不作为独立大项执行；充电相关判断在中/高负载和结束大项内完成
失败不终止小项失败只跳过当前大项，继续往后跑；只有温度超红线才立即终止整个老化
失败位置不单独上报失败大项/小项，见 4A.5 的说明
已运行时长elapsed_ms 跨重启累加，重启那 1~3 s 不计入；不使用 RTC，无额外常驻功耗
重启后等待每次重启后至少 30 s 才执行下一步；该窗口内仍可发停止/退出
喂狗老化线程优先级最低，长时间等待均按 100 ms 分片，期间可响应命令，不会阻塞看门狗
总线大项依赖I2C 压力大项编译在 __SNDP_AGING_ITEM_SENSOR__ 下，与传感器小项同开关
音频采集路数采集通道数按板级 MAINMIC 实际路数计算（本项目为 2 路麦 + 1 路参考 = 3 路），数目不符会导致 codec 断言复位
产线怎么用
  1. 治具上电，pogopin 单线 UART 按 115200 8N1 打开
  2. 发 0x7D 下发配置（参数见 4A.3），确认返回成功；可用 0x7E 回读核对
  3. 发 0x7A（无 DATA）启动
  4. 过程中周期发 0x7C 看当前大项/小项、各大项轮次与耗时、温度、电压
  5. 软重启阶段不要重复发启动，耳机自己从分区续跑
  6. 结束后再查一次：running = 0 且 curr_fail_code = 0 为通过
  7. 要放弃本次、不让下次开机续测，发 0x7D 且 DATA 为 1 字节 0x00，不要只发停止

本项目无硬件电量计，电量通过 ADC 读电池电压换算（软电量计）。因此：

  • A/B 点的准确性依赖电压→电量曲线，需确认该曲线已标定
  • 大电流工况（如 B6 高负载）下，ADC 读到的电压会因内阻压降偏低，需在软件中做内阻补偿，否则会出现"A/B 点误判"

12. 管控红线（温度 / 电量）

温度红线：全程 ≤ 50 ℃

老化全流程循环读取电池温度（NTC → ADC）。

一旦温度 > 50 ℃，立即停止老化并记录为 Fail。

注：B6 高负载阶段是主要发热来源，需重点监控温升速率与稳态温度。

管控项门限动作检测方式
电池温度 ≤ 50 ℃ 超限 → 立即停止老化，判定 Fail ADC 读 NTC
充电启动点（A） < 50% 启动充电 ADC 读电池电压换算
充电停止点（B） > 80% 暂停充电 同上
老化后补电目标 80% ~ 85% 低于 80% 持续补电，到 80% 停充（终检大项内执行） 同上
